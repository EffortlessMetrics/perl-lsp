# v0.17.0

## Summary

Minor release. A unified Perl toolchain profile shared across LSP, DAP, and
first-run diagnostics; automatic `.perltidyrc` discovery honored by the default
native formatter; a first-run `perllsp --doctor` setup report; richer symbol
and hover coverage (`our` variables, Moo/Moose `has` attributes, phase blocks,
workspace method signature help); framework-aware inline completions; and a
broad pass of DAP and LSP correctness fixes.

## What improved for users

- **One Perl interpreter across LSP and DAP.** Debug sessions now resolve the
  Perl interpreter through the same shared toolchain profile as analysis
  (perlbrew → plenv → `PATH`) when `launch.json` omits an explicit `perl`, with
  cached version probing. An explicit `launch.json` `perl` is still honored, and
  resolution falls back to `"perl"` so the existing "perl not on PATH"
  diagnostic is preserved. (#1929, #1951, #1978)

- **Automatic `.perltidyrc` discovery, honored by the default formatter.** When
  no `perltidy_profile` is configured, the server discovers a project-local
  `.perltidyrc` once at `initialize` (workspace root → `PERLTIDY` env override →
  `$HOME/.perltidyrc`) and applies its supported scalar options in the **default
  native** formatter — not just `external-legacy` mode. Precedence: built-in
  defaults < discovered profile < explicit `.perl-lsp.toml` /
  `didChangeConfiguration`. (#1899, #2016, #2025, issues #1777, #1953)

- **First-run doctor report.** `perllsp --doctor [dir]` prints a read-only setup
  report covering project config, Perl interpreter probing, configured include
  roots, `PERL5LIB`, system `@INC`, rejected roots, and the effective
  include-root categories — with stderr guidance preserved on failed version
  probes. (#1571, issue #1818)

- **Richer outline and symbol coverage.** `our` package variables and Moo/Moose
  `has` attributes are now indexed and appear in document/workspace symbols and
  go-to-symbol. Workspace method signature help resolves `->method()` signatures
  from the project symbol index. (#1300, #1301)

- **Phase-block hover docs.** Hovering `BEGIN`/`END`/`INIT`/`CHECK`/`UNITCHECK`
  explains when that block runs relative to compile and runtime. (#1298)

- **Framework-aware inline completions.** Try::Tiny `try`/`catch`,
  Mojolicious::Lite / Dancer route scaffolds, and project-indexed package
  receiver method completions are offered only when workspace evidence supports
  them, and stay quiet in strings, regex, heredoc bodies, and POD. (#1532,
  #1573, #1585, #1949, issue #1648)

- **VS Code first-run onboarding.** The extension can suggest discovered include
  paths from common Perl module directories, exposes an optional server-gated AI
  completion walkthrough, and ships an openable demo project. (#1898)

- **Editor settings that actually take effect.** `enableSemanticTokens` and
  `enableFormatting` are now honored at runtime; two no-op settings
  (`enableDiagnostics`, `enableRefactoring`) were removed. (#1290)

## What changed for editor integrations

- **Debugger (DAP) correctness.** Stale stack frames are cleared on resume;
  degraded-transport `stackTrace` returns empty rather than stale; structured /
  container `evaluate` results expand in the variables view; invalid
  `variablesReference` returns a safe empty response; typed reference codec
  retires the scope/stack/evaluate collision class; execution-control and
  `pause` requests return accurate no-session vs failure guidance; request
  ordering (`launch` after `initialize`, `configurationDone` after a session) is
  enforced; scopes expose `namedVariables`/`indexedVariables` and variables
  expose `totalVariables`; capability flags match implemented handlers;
  non-request transport messages are handled explicitly; and the event handler
  fails closed after persistent transport failure. (#1219, #1227, #1240, #1337,
  #1364, #1430, #1444, #1496, #1498, #1759, #1790, #1806, #1807, #1809, #1810,
  #1811, issues #1608, #1609)

- **LSP robustness and documentation surfaces.** Bare absolute paths are
  accepted as `file://` URIs; malformed `signatureHelp` and pre-`didOpen`
  semantic-token requests return actionable guidance; multi-root
  `workspace/symbol` is deterministic and folder-scoped; indexing counters stay
  truthful after duplicate parse-complete signals; reference fallback avoids
  document-lock re-entry; PL701 missing-module diagnostics point at
  `perllsp --doctor` and the docs URL; one validated resolver backs all Perl doc
  links; POD `L<>` references are clickable, non-standard `=head1` sections are
  indexed, and POD hover refreshes after external edits; hover escapes markdown
  metacharacters; completions carry `filterText`, advertise insert text modes,
  include inherited methods, group semantic tiers, and stay quiet in
  strings/regex/heredoc/POD. (#1206, #1290, #1300, #1301, #1298, #1522, #1551,
  #1597, #1638, #1795, #1834, #1838, #1840, #1841, #1875, #1882, #1889, #2047,
  #2606, issues #1610, #1712, #2049, #2553)

## Install / package / release path

No changes to the install path or packaging in this release. `cargo install
perllsp` and `cargo install perl-dap` are expected to work; the package-content
CI gate continues to guard the crates.io publish.

Channels are pending publish; the release sync prepares the version strings and
release artifacts only. Tag and publish happen via `release-orchestration.yml`
with explicit approval.

## Known limitations

### Proof burndown exceptions (active)

Proof-lane burndown exceptions remain active and are documented in
`policy/quality-gate-exceptions.toml`:

- **`ripr-total-burndown`** — existing repo-wide RIPR+ gaps are burned down with
  focused proof PRs; new gaps are hard-blocked. Final target: repo-wide RIPR+
  unresolved total = 0. (#8197)
- **`project-coverage-burndown`** — project coverage is below the final 95%
  floor while patch coverage is blocking first. Final target: workspace project
  coverage ≥ 95%. (#8197)

Neither exception permits new RIPR+ gaps on incoming PRs.
