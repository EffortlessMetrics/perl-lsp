# v0.16.0

## Summary

Minor public-alpha release. This release substantially expanded deterministic,
project-aware inline completion; added several editor quick fixes and gated LSP
3.18 surfaces; improved Perl syntax coverage across modern and ecosystem code;
hardened DAP stack and variable inspection; introduced navigable workspace POD
virtual documents; and established stronger release smoke and proof gates.

## Historical provenance correction

The `v0.16.0` source tree was promoted from `perl-lsp-swarm` RC
`a87f766ab60da513833dfff47349384be96fdae2` through source commit `6925335fa4a5c142b3ce35b0134104b753b7ffd9`
([PR #9909](https://github.com/EffortlessMetrics/perl-lsp/pull/9909)) as a
**content-state mirror**. That promotion preserved the complete release tree but
did not make the individual swarm squash-merge commits ancestors of `v0.16.0`.

The missing logical ancestry was later connected to `perl-lsp` by the
history-preserving 0.17 sync. Therefore:

- `v0.15.2...v0.16.0` accurately describes the source-tree delta, but it is not
  a complete logical-commit ledger for this release;
- the canonical development boundary is swarm merge-base `151c5ecee69ef465836d2e7e173c310690391574` through
  RC `a87f766ab60da513833dfff47349384be96fdae2`;
- the release items below were reconstructed from the RC tree, logical swarm
  squash commits, source sync PR, and behavior tests rather than from the source
  tag range alone.

No source or review history was permanently lost; the defect was the ancestry
of the 0.16 tag and the resulting release accounting.

## What improved for users

### Project-aware inline completion

- **Declared-variable test assertions.** Test::More and Test2 files can suggest
  conservative `ok(...)` and `is(...)` statements using visible declared
  scalars instead of hard-coded placeholder names. Suggestions remain import-
  gated and stay quiet outside supported test contexts.
  (EffortlessMetrics/perl-lsp-swarm#497)
- **Current-package receiver methods.** Self-like receiver completion can use
  methods declared in the current package, including partial-fragment
  replacement ranges. (EffortlessMetrics/perl-lsp-swarm#504)
- **Style-aware constructors.** Generated constructor bodies follow the local
  file style: signatures, `@_` extraction, or `shift`-based code.
  (EffortlessMetrics/perl-lsp-swarm#523)
- **Workspace module completion.** `use` and `require` ghost text can suggest
  reachable project modules from effective include roots and the live workspace
  index. (EffortlessMetrics/perl-lsp-swarm#529,
  EffortlessMetrics/perl-lsp-swarm#564)
- **Receiver and collection context.** DBI database/statement handles, visible
  arrays and hashes for loop bindings, partial return variables, and visible
  scalars in condition expressions now drive deterministic candidates instead
  of generic placeholders. (EffortlessMetrics/perl-lsp-swarm#536,
  EffortlessMetrics/perl-lsp-swarm#540,
  EffortlessMetrics/perl-lsp-swarm#542,
  EffortlessMetrics/perl-lsp-swarm#729,
  EffortlessMetrics/perl-lsp-swarm#736)
- **Confidence ranking and parse safety.** Candidate ranking incorporates source
  confidence, and candidates that clearly worsen parser recovery are rejected.
  (EffortlessMetrics/perl-lsp-swarm#513,
  EffortlessMetrics/perl-lsp-swarm#517)
- **Hard reject zones and safe ranges.** Ghost text stays out of strings,
  comments, heredoc bodies, POD, and regex literals. Replacement ranges are
  validated and clamped before reaching clients, and automatic triggers return
  only the top deterministic candidate while explicit invocation can return the
  richer set. (#9621, #9626, #9631)

### Code actions and CodeLens

- **PL405 printf/sprintf arity fix.** A guarded quick fix can insert missing
  `undef` arguments for supported parenthesized and listop call shapes while
  failing closed on unsafe enclosing ranges.
  (EffortlessMetrics/perl-lsp-swarm#430)
- **Recognized-function import fix.** Undefined bareword function diagnostics
  can offer imports for recognized common module functions, such as JSON and
  File::Basename helpers. (EffortlessMetrics/perl-lsp-swarm#856)
- **PL410 loop-label fix.** `next`, `last`, and `redo` diagnostics can remove an
  undefined label while preserving the underlying loop-control operator.
  (EffortlessMetrics/perl-lsp-swarm#1172)
- **CodeLens resolution and tooltips.** Clients advertising command resolve
  support can receive lazy command lenses; unsupported clients retain eager
  commands. CodeLens commands also carry deterministic plain-text tooltips.
  (EffortlessMetrics/perl-lsp-swarm#500,
  EffortlessMetrics/perl-lsp-swarm#514)

### Perl parser and lexer coverage

The parser accepted a substantially broader set of valid Perl syntax, including:

- scalar filehandle readline (`<$fh>`) as `Readline`, not glob;
- optional versions on native `class` declarations;
- parenthesized builtins followed by ternaries;
- unbraced dereferences (`$$ref`, `@$ref`, `%$ref`);
- Perl 5.22+ double-diamond `<<>>`;
- full scalar expressions in signature defaults;
- assignment to lvalue builtins such as `pos`, `substr`, and `vec`;
- lowercase Perl 5.32+ `isa` infix expressions;
- trailing method attributes after signatures;
- valid empty-search `tr///` character-count forms;
- three-part version directives such as `use 5.10.1;`;
- methods named after quote operators (`method y`, `method s`, `method tr`);
- parenthesized variable-attribute arguments.

The parser error classifier also became UTF-8 boundary-safe when producing
source snippets. Representative work:
EffortlessMetrics/perl-lsp-swarm#708, #711, #715, #725, #744, #754, #759,
#762, #770, #771, #775, #784, #801, and #802.

### Documentation and semantic presentation

- **Perldoc / POD virtual documents.** `perldoc://` links resolve to workspace
  POD content. Labels in `=head2` and `=item` sections become navigable targets,
  and module links prefer workspace-local POD before external `perldoc`. (#1186)
- **Semantic labels.** Perl statement and control labels (`LOOP:`, `BLOCK:`) use
  the semantic-token `label` type.
- **VS Code setup guidance.** The extension shows a corrected remediation message
  when the `perl` executable cannot be found.

### Debug adapter behavior

- **Current-stop stack selection.** Framed debugger output and the session's
  latest authoritative stack state are preferred over parsing the entire
  historical output buffer, which could otherwise surface an earlier stop.
- **Lexical locals inspection.** Locals are read from the current Perl frame's
  pad through the `B` module instead of treating lexical variables as package
  symbol-table entries. This avoids fake DB-internal fallback values when real
  `my` variables are available.
- **Real transport and content receipts.** The DAP test surface gained packaged
  stdio framing, lifecycle, scope-filtering, setVariable content, and live
  evaluate coverage.

### OpenAI-compatible connector configuration

Inline AI connectors can configure the API-key header and prefix rather than
being forced to use a Bearer `Authorization` header. Header names, prefixes, and
key content are validated before request construction.
(EffortlessMetrics/perl-lsp-swarm#739)

## What changed for editor integrations

- **LSP 3.18 applyEdit metadata.** `workspace/applyEdit` requests include
  `label`, `description`, and `isRefactoring` only when the client advertises
  the corresponding support. (#1184)
- **Capability-gated LSP 3.18 functionality.** Supporting clients can receive
  `CompletionList.itemDefaults.data`, `CompletionList.applyKind.data`, static
  code-action documentation, snippet-aware current-document pragma edits,
  applyEdit metadata, and lazy CodeLens command resolution. Unsupported clients
  retain compatible fallback shapes. (EffortlessMetrics/perl-lsp-swarm#525,
  #530, #534, #592, #657)
- **Claim and negative-contract locks.** Tests and the LSP 3.18 claim guard
  prevent these fields from being emitted without the matching client
  capability. (#9628)
- **Inline completion registration.** Static clients receive top-level
  `inlineCompletionProvider`; dynamic-capable clients receive
  `client/registerCapability`. The obsolete experimental capability is not
  emitted.
- **Folding refresh receipt.** `workspace/foldingRange/refresh` has a positive
  capability-gated wire receipt. (#9633)

## Internal boundaries and non-claims

- **Next-edit remained disabled.** The release added a configuration boundary,
  safety policy, and receipt-only candidate proofs for future deterministic
  next-edit families. No next-edit LSP provider was registered, no editor-visible
  next-edit suggestions were emitted, and optional AI next-edit behavior stayed
  disabled.
- **Proof infrastructure is not a product feature.** RIPR new-gap enforcement,
  Patch-95 routing, semantic-inline receipts, and product smoke fixtures validate
  the release but should not be read as additional user-facing behavior.

introduced in 0.15.2 continues to guard the crates.io publish.

## Known limitations

### Release-history boundary

The logical swarm commits are not ancestors of `v0.16.0`; they became reachable
from the canonical repository through the later 0.17 history-preserving sync.
Do not use the source tag comparison as the sole input for historical changelog
or authorship analysis.

### Proof burndown exceptions (active at the cut)

Two proof-lane burndown exceptions were documented in
`policy/quality-gate-exceptions.toml`:

- **`ripr-total-burndown`** — existing repo-wide RIPR+ gaps predated the
  transition gate; new gaps were blocked while existing clusters were burned
  down. Final target: zero unresolved RIPR+ gaps. (#8197)
- **`project-coverage-burndown`** — project coverage remained below the final
  95% floor while patch coverage became blocking first. (#8197)

Neither exception permitted new RIPR+ gaps on incoming PRs.
