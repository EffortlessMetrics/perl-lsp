# v0.15.0

## Summary

Minor release focused on JSON-RPC type safety and fixing the LSP4IJ file-watcher
registration crash that prevented JetBrains users from running perl-lsp.

Two breaking changes in the public `perl-lsp-rs-core::protocol` crate API
(`JsonRpcRequest.id` / `JsonRpcResponse.id` field type; `outbound::send_request`
parameter type) lift this from a patch to a minor version under 0.x semver.

## Highlights

### For users

- **JetBrains/LSP4IJ users can now run perl-lsp.** The server previously
  generated `client/registerCapability` request IDs from
  `SystemTime::now().as_millis()` - values around 1.7e12, which overflow
  `i32::MAX` (~2.1e9). LSP4IJ and other strict LSP clients reject those
  IDs and crash on workspace initialization. The fix routes all
  server-to-client requests through a bounded `AtomicI32` allocator that
  emits sequential positive `i32` values, wrapping from `i32::MAX` back
  to `1`.

- **Inbound request IDs of invalid shape (null, fractional, object,
  array) are rejected at the transport boundary** instead of being
  silently coerced or producing undefined behavior deep in the
  dispatcher.

### For contributors

- **Typed JSON-RPC IDs end-to-end.** The cancellation registry, dispatch
  surfaces, runtime cancellation set, and progress-token-to-request map
  all now key on `JsonRpcId` instead of `serde_json::Value`. The
  `format!("{:?}", value)` keying that previously stood in for proper
  hashing is gone. Integer and string IDs with the same textual form
  are now independently cancellable.

- **`ServerRequestId`** newtype around a positive `i32`. The only
  public constructor is `new(i32) -> Option<Self>` plus boundary
  helpers. It is now structurally impossible to construct a
  server-generated request ID outside the LSP4IJ-safe range.

- **Source-guard tests** in `lsp4ij_request_id_regression.rs` pin
  `lifecycle/watchers.rs` against re-introducing wall-clock IDs or
  bypassing the shared allocator.

## Breaking changes

### `perl-lsp-rs-core::protocol::JsonRpcRequest` and `JsonRpcResponse`

```rust
// Before (0.14.x)
pub struct JsonRpcRequest {
    pub id: Option<serde_json::Value>,
    // ...
}

// After (0.15.0)
pub struct JsonRpcRequest {
    pub id: Option<JsonRpcId>,
    // ...
}
```

**Migration:** consumers constructing `JsonRpcRequest` / `JsonRpcResponse`
in tests or external code switch from `Some(json!(1))` /
`Some(json!("abc"))` to `Some(JsonRpcId::Integer(1))` /
`Some(JsonRpcId::String("abc".into()))`. Convert to `Value` at the wire
boundary via `id.to_value()`. Convert from `Value` via
`JsonRpcId::from_value(&value)` (returns `Option` - invalid shapes
yield `None`).

### `outbound::OutboundSender::send_request`

```rust
// Before
pub fn send_request(&self, id: i64, method: &str, params: Value) -> io::Result<()>

// After
pub fn send_request(&self, id: ServerRequestId, method: &str, params: Value) -> io::Result<()>
```

**Migration:** allocate IDs through `LspServer::next_server_request_id`
or `LspServer::send_request` rather than passing raw integers. If you
must construct one in test code, call
`ServerRequestId::new(positive_i32)` and handle `None`.

### Cancellation registry signatures

`CancellationRegistry`, `PerlLspCancellationToken`, and
`RequestCleanupGuard` now key on `JsonRpcId`. Call sites that previously
passed `&serde_json::Value` now pass `&JsonRpcId`. Convert at the
boundary via `JsonRpcId::from_value(&value)`.

Post-0.15.0 note: the setup docs now treat LSP4IJ as an upstream integration
path. Use the upstream LSP4IJ `perl-lsp` entry when available; manual Raw
Command setup remains documented separately for older plugin versions and local
development.

## Claim boundary

This release contains: the JSON-RPC ID type-safety migration (#221,
#223), the LSP4IJ file-watcher crash fix (#221), and the cancellation
registry typed migration (#223). It is the **crash unblock** for
JetBrains users.

It does NOT contain: the latency rail (PRs 2-10 of the
[interactive latency ladder](../development/LSP_INTERACTIVE_LATENCY_ROLLOUT.md)),
incremental AST reuse, or `TextDocumentSyncKind` changes. Those are
explicitly deferred to keep the breaking-change window small.
