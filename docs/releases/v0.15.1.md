# v0.15.1

## Summary

Patch release delivering the interactive-latency rail for lean editor workflows,
standards-compliant LSP4IJ inline-completion registration, and a semantic-token
capability correction. The release adds explicit workload controls for isolating
first-useful hover and completion from avoidable background work and cancels
stale read requests when the document advances.

The checked-in receipts prove wiring and behavior boundaries. They do not claim
hardware-independent latency targets or true incremental AST reuse.

## What improved for users

### Lean editor and latency controls

- **E2E workload mode.** `--runtime-mode e2e` / `PERL_LSP_E2E=1` applies a lean
  harness profile: zero diagnostic debounce, syntax-only diagnostics, no eager
  workspace indexing, and no file watchers by default. This is a workload
  profile for editor and integration testing, not a separate feature set.
- **Syntax-only diagnostics.** `--diagnostic-mode syntax-only` /
  `PERL_LSP_DIAGNOSTIC_MODE=syntax-only` restricts both push and pull diagnostic
  paths to parser errors. It skips semantic diagnostics, native and external
  Perl::Critic passes, module-resolution checks, and workspace dead-code work.
- **Configurable diagnostic debounce.** `--diagnostic-debounce-ms <ms>` /
  `PERL_LSP_DIAGNOSTIC_DEBOUNCE_MS=<ms>` controls the publish debounce window;
  `0` bypasses the debouncer for latency-focused harnesses.
- **No eager indexing in E2E mode.** `initialized` no longer starts a workspace
  scan under the E2E profile unless `--eager-workspace-indexing=true` explicitly
  restores it.
- **Generation-aware stale-read cancellation.** Hover, completion, definition,
  declaration, type definition, implementation, and references are cancelled
  with `RequestCancelled` when the document generation advances between request
  ingress and dispatch. Typing storms therefore converge on the latest document
  instead of completing work for every stale cursor position.
- **Watcher suppression is honored.** `--file-watchers=false` prevents dynamic
  file-watcher registration while leaving unrelated feature registrations, such
  as inline completion, available.

### LSP4IJ inline completion

- **Standards-based registration.** Static clients receive top-level
  `inlineCompletionProvider`. Dynamic-capable clients advertising
  `textDocument.inlineCompletion.dynamicRegistration` receive
  `client/registerCapability` after `initialized`.
- **No obsolete experimental capability.** `experimental.inlineCompletionProvider`
  is not emitted. The separate custom `experimental.perlInlineCompletionStream`
  entry remains available without replacing other experimental entries.
- **Runtime execution receipt.** An LSP4IJ-shaped JSON-RPC client opens a Perl
  document and proves `textDocument/inlineCompletion` returns deterministic
  suggestions at supported positions, including `strict;` after a `use ` prefix.
- **Bounded outbound request IDs remain enforced.** Dynamic registrations route
  through `LspServer::send_request` and the typed bounded request-ID allocator
  introduced in 0.15.0.

### Capability and provider diagnostics

- **Semantic tokens advertise full-only support.** The server no longer claims
  delta support before the result-ID and delta-response path exists.
- **Provider-decision explanation surface.** `perl.explainProviderDecision`
  returns a structured provider-decision payload and reports a conservative,
  low-confidence `missing_fact` / `no_result` fallback when no provider-specific
  receipt is attached.

## Validation performed

- Raw-RPC editor-loop receipts cover E2E startup, syntax-only diagnostics,
  watcher suppression, and deterministic inline-completion execution.
- A Neovim lean smoke path exercises the documented workload flags.
- Capability snapshots and registration tests lock full-only semantic tokens and
  static-versus-dynamic inline-completion negotiation.

These are behavior and wiring receipts. Numeric latency targets require a
release build and dedicated hardware measurements; this release does not claim
that the benchmark targets in the latency rollout were achieved universally.

## Install-surface caveat

The crates.io package for `perl-lsp-rs-core` 0.15.1 omitted
`build_catalog.rs`. As a result, `cargo install perllsp --version 0.15.1` and
`cargo install perl-dap --version 0.15.1` failed while building dependencies from
crates.io. The source/tag behavior described above remains the 0.15.1 product
change, but Cargo users should install **0.15.2 or later**, which restored the
missing package content and added an unpacked-package verification gate.

## Claim boundary

This release contains the lean editor workload controls, generation-aware stale
read cancellation, standards-based LSP4IJ inline-completion registration,
deterministic inline-completion execution receipts, full-only semantic-token
advertisement, and the conservative provider-decision explanation surface.

It does **not** implement:

- true incremental AST reuse after `didChange`;
- semantic-token delta responses or result-ID caching;
- new AI inline-completion backend behavior;
- a universal wall-clock latency guarantee;
- a change to `TextDocumentSyncKind`.
