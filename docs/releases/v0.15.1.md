# v0.15.1

## Summary

Patch release focused on LSP4IJ inline completion and lean editor-mode
hardening.

## Highlights

### For users

- **LSP4IJ inline completion now uses one registration mode.** Static clients
  receive top-level `inlineCompletionProvider: {}`. Dynamic-capable clients that
  advertise `textDocument.inlineCompletion.dynamicRegistration` receive
  `client/registerCapability` for `textDocument/inlineCompletion` after
  `initialized`.
- **Inline completion has a runtime result receipt.** A real JSON-RPC path with
  an LSP4IJ-shaped client opens a Perl document and proves
  `textDocument/inlineCompletion` returns deterministic suggestions for
  supported positions, including `strict;` after `use `.
- **Lean editor mode avoids watcher and startup noise.** The e2e profile keeps
  file watchers and eager workspace indexing off when requested, while still
  allowing feature-specific dynamic registration such as inline completion.
- **Semantic tokens no longer overclaim delta support.** The server advertises
  full semantic-token support without delta until the result-id/delta path is
  implemented.

### For contributors

- `experimental.inlineCompletionProvider` must not be emitted. The standard
  capability is top-level `inlineCompletionProvider`, or dynamic registration
  for clients that opt into `textDocument.inlineCompletion.dynamicRegistration`.
- `experimental.perlInlineCompletionStream` remains a custom extension and must
  be merged into `experimental` without replacing other entries.
- Dynamic server-to-client registrations continue to use the bounded request ID
  allocator through `LspServer::send_request`.

## Claim boundary

This patch proves LSP4IJ discovery, dynamic registration, and deterministic
inline-completion execution for supported Perl positions. It also proves the lean
profile avoids file-watcher registration and does not advertise semantic-token
delta support.

It does not implement incremental AST reuse, semantic-token delta responses, or
new AI inline-completion backend behavior.
