# Swarm Methodology Improvements Roadmap

*Concrete fixes, process improvements, and quality ratchets discovered across cycles 1-5 of perl-lsp swarm development.*

---

## Executive Summary

Five cycles of swarm development (March 2026) with up to 100 concurrent agents have revealed systematic gaps in the methodology. This document catalogs every discovered improvement, categorized by urgency, estimated effort, and implementation plan.

The improvements fall into three tiers:
- **7 critical fixes** that directly cause agent failures or wasted work
- **12 tactical process improvements** that increase throughput and reduce friction
- **5 missing quality ratchets** that would prevent regression

---

## Critical Fixes (Blocking or High-Waste)

### 1. Auto-Status Update After Test Changes

**Problem**: Every agent that adds tests changes the test count. The `policy_checks` CI gate verifies that `docs/project/CURRENT_STATUS.md` matches actual test counts. Result: 4/5 PRs in review-batch-1 (cycle 5) were blocked by stale test counts.

**Root Cause**: `CURRENT_STATUS.md` is generated by `scripts/update-current-status.py` but agents don't run it after adding tests.

**Fix**: Add `python3 scripts/update-current-status.py --write` to the `/verify-build` skill, so every agent that runs verification also updates status.

**Status**: Skill updated in cycle 5, but not yet in the canonical skill file on master.

**Effort**: 15 minutes (skill update) + 30 minutes (verify it works end-to-end)

**Impact**: Eliminates #1 merge friction point

### 2. Corpus Ratchet Hook

**Problem**: Parser fixes merge to master but the CPAN corpus baseline isn't updated. In cycle 5, the gap between actual coverage (~85%) and ratcheted baseline (80%) represented 200+ files of "free" improvement sitting unclaimed.

**Root Cause**: `just cpan-corpus-ratchet` is a manual step that gets forgotten in the merge flow.

**Fix**: Create a post-merge-wave step (or CI workflow) that automatically runs corpus ratchet when parser fix PRs merge. Alternatively, add a `/corpus-ratchet` skill that combines sweep + baseline update + manifest update + PR creation.

**Effort**: 2-3 hours (skill creation + CI integration)

**Impact**: Eliminates stale baselines, makes corpus metrics accurate in real-time

### 3. Phantom Bucket Audit

**Problem**: The SEMANTIC_BUCKETS mapping in `xtask/src/tasks/parser_corpus_sweep.rs:33-84` contains bucket names that don't correspond to actual parser error strings. Bucket #5 (`unexpected_rbrace_expr`: 83 files) was initially identified as phantom — the substring match caught errors that were misclassified.

**Root Cause**: Bucket definitions were written early and never validated against the evolving parser error messages. First-match-wins substring matching creates order-dependent classification.

**Fix**:
1. Audit every bucket name against actual `ParseError::unexpected()` output
2. Add a validation step that ensures every bucket maps to a real error pattern
3. Reorder or restructure substring matching to eliminate ambiguity

**Effort**: 3-4 hours (audit + restructure + revalidate corpus)

**Impact**: Accurate corpus metrics, elimination of misclassified files

### 4. Dedup Scout Pass Before Builders

**Problem**: In cycle 5, 4 builder agents discovered their work was already done — PRs had already merged fixing their target issues. That's 4 wasted agent slots + compute time.

**Root Cause**: Builders were launched from the issue list without checking if related PRs had already merged.

**Fix**: Before launching any builder, run: `gh pr list --state merged --search "fixes #<issue>"`. Codify this as the first step in the builder prompt template or as a hook.

**Effort**: 30 minutes (add to prompt template)

**Impact**: Saves ~5-10% of agent compute per session

### 5. Assert Fix in Agent Verification

**Problem**: Agents that add tests but include `assert!()` or `unwrap()` fail the clippy gate because these are banned in production code. Test code has different rules (use `Result<()>` returns or `perl_tdd_support::must/must_some`).

**Root Cause**: Agents don't know the test code conventions unless they're explicitly told.

**Fix**: Add test code conventions to the `/coding-standards` skill or inject them via the `SubagentStart` hook. Specifically: "In tests, use `Result<()>` returns or `perl_tdd_support::must`/`must_some` — never `unwrap()` or `expect()`."

**Effort**: 30 minutes (skill update)

**Impact**: Reduces test agent failure rate from ~20% to ~5%

### 6. Clippy Gate on Master Before Building

**Problem**: In cycle 4, the clippy gate was failing on all PRs because master itself had clippy warnings. All builder output was blocked until clippy was fixed on master. This should have been Phase 1.5 but wasn't prioritized.

**Root Cause**: Merged PRs introduced clippy warnings that weren't visible on individual branches but appeared in merge commits.

**Fix**: Check master CI health as the FIRST action of every session. If master is red, fix it before launching any builders. Add to session startup checklist.

**Effort**: 15 minutes (checklist update), variable time to fix clippy

**Impact**: Prevents entire-session blockage

### 7. Single-File CPAN Parsing Tool

**Problem**: Scout agents investigating CPAN error buckets couldn't easily parse individual CPAN files to reproduce errors. They had to construct ad-hoc commands.

**Root Cause**: No `xtask parse-file <path>` command exists.

**Fix**: Add an `xtask` subcommand that parses a single file and outputs the AST or error details.

**Effort**: 2-3 hours (xtask implementation + tests)

**Impact**: Accelerates scout investigation by ~50% per file

## Tactical Process Improvements

### 8. Wave Pattern Codification

**Current**: Agents are launched ad-hoc. The wave pattern emerged organically:
```
Wave 1: Triage existing PRs → cluster → compare → keep best → close rest
Wave 2: Research scouts → root cause analysis → create issues
Wave 3: Targeted builders using scout findings as prompts
Wave 4: Test coverage across every crate
```

**Improvement**: Codify this pattern in the `/swarm` skill with explicit phase transitions and capacity allocation per wave.

**Effort**: 1-2 hours

### 9. Research-to-Build Handoff Format

**Current**: Scout findings are written as prose in issue bodies or memory files. Builders extract the relevant information manually.

**Improvement**: Standardize the handoff format:
```
{function: "consume_use_import_value",
 file: "crates/perl-parser-core/src/engine/parser/declarations.rs",
 line: 952,
 construct: "use if $condition, 'Module'",
 fix_approach: "Allow keywords as barewords in use context",
 sample_files: ["Foo.pm:23", "Bar.pm:45"]}
```

The builder prompt template fills from this structure directly.

**Effort**: 1 hour (template update)

### 10. Merge Queue Skill

**Current**: Merging is manual — check CI, merge in batches of 3, wait for CI, repeat.

**Improvement**: Create a `/merge-queue` skill that:
1. Lists green PRs ordered by priority
2. Merges in batches of 3
3. Waits for CI between batches
4. Reports results

PR #2121 implements this skill.

**Effort**: Already implemented, needs merge

### 11. Agent Count Budget Planning

**Current**: Agents are spawned until the platform ceiling is hit (~75).

**Improvement**: Plan agent budget upfront based on merge queue math:
- Coding agents: ~9 (merge queue width x work time / CI time)
- Scouts: ~15 (cheap, no PRs)
- Reviewers: ~5 (1 per PR batch)
- Reserve: ~10 (late-cycle routing)
- Total planned: ~39

Leave remaining capacity as overflow queue using GitHub issues.

**Effort**: 30 minutes (add to session startup)

### 12. Stale Issue Cleanup

**Current**: All 8 open refactoring issues in cycle 5 were already resolved. Issues weren't closed when their PRs merged.

**Improvement**: Use `Fixes #N` in PR bodies so GitHub auto-closes issues on merge. Add a session-start issue audit pass.

**Effort**: 15 minutes (PR body template update)

### 13. Worktree Freshness Check

**Current**: Worktree agents work on branches that drift from master. Long-lived branches produce correct diffs but broken checkouts.

**Improvement**: Add a pre-PR-creation check: "is this branch within N commits of master?" If not, rebase first. Add to `/verify-build` skill.

**Effort**: 30 minutes

### 14. Parallel Bash Call Isolation

**Current**: Mixing state-changing commands (`git pull`) with read-only queries (`gh pr list`) in parallel Bash calls causes cascade failures — all calls fail if one fails.

**Improvement**: Document the rule: state-changing commands first (sequential), then parallel reads. Add to known pitfalls.

**Effort**: 15 minutes

### 15. Review Agent Checkout Requirement

**Current**: Review agents read diffs. Diffs can show correct changes while the branch is broken.

**Improvement**: Review agents must checkout the branch and build it, not just read the diff. Add to review prompt template.

**Effort**: 30 minutes

### 16. Version Consistency Check

**Current**: Version strings drift across 130+ Cargo.toml files with no CI check.

**Improvement**: Add `just version-check` recipe and include it in release checklist and optionally in CI.

**Effort**: 1-2 hours

### 17. Agent Experience Reports

**Current**: Agents complete work and shut down. Learnings are lost.

**Improvement**: Agents write brief experience reports before shutdown: what worked, what was unexpected, what blocked them. Capture via TaskCompleted hook or final prompt step.

**Effort**: 30 minutes (hook or prompt update)

### 18. Security Audit Cadence

**Current**: Ad-hoc security audits when someone remembers.

**Improvement**: One security audit per release cycle (not every session). The cycle 5 audit found zero issues — the investment compounds. More frequent audits waste agent time.

**Effort**: 15 minutes (add to release checklist)

### 19. Idle Agent Recycling

**Current**: Agents that finish early sit idle. New agents can't be spawned due to roster ceiling.

**Improvement**: Use `SendMessage` to reassign completed agents to new tasks from the issue queue. This was discovered in cycle 5 as a ceiling escape hatch.

**Effort**: Already working, needs documentation

## Missing Quality Ratchets

### 20. Benchmark Regression Baseline

**Current**: Criterion benchmarks exist but have no baseline tracking. Performance regressions are invisible.

**Fix**: Store benchmark results as JSON, compare on each PR, fail CI if regression exceeds threshold.

**Issue**: #2091 (estimated 4 hours)

### 21. Flaky Test Detection

**Current**: Flaky test infrastructure exists but tracks 0 tests. No auto-quarantine.

**Fix**: Run tests multiple times in CI, track failure rates, quarantine tests that fail >5% of runs.

**Issue**: #2093 (estimated 6 hours)

### 22. Test Taxonomy (Smoke/Deep/Slow)

**Current**: 900+ integration tests all run on every PR (~20+ minute feedback).

**Fix**: Categorize tests into tiers: smoke (PR-fast, <1 min), deep (merge gate, <5 min), slow (nightly, <30 min). Run only the appropriate tier based on context.

**Issue**: #2096 (estimated 5 hours)

### 23. Branch Coverage Gating

**Current**: Line coverage is tracked. Branch coverage is not.

**Fix**: Add branch coverage reporting and set minimum thresholds for new code.

**Issue**: #2099 (estimated 4 hours)

### 24. Corpus Classification Validation

**Current**: SEMANTIC_BUCKETS mapping is not validated against actual parser output.

**Fix**: Add a validation script that confirms every bucket matches real error strings. Run as part of corpus sweep.

**Effort**: 2-3 hours (new xtask check)
