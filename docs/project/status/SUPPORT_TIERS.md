# Support Claim Map

> Human-owned. This page maps user-facing `perl-lsp` claims to proof commands,
> status docs, known limitations, and next promotion proof.

This page is a claim boundary, not a marketing page. Generated parser and
semantic status remains the source of current measurements. Provider confidence
state remains in [provider_confidence_matrix.md](provider_confidence_matrix.md)
and [provider_cutover.md](provider_cutover.md).

## Tier Vocabulary

| Tier | Meaning |
| --- | --- |
| `measured-bounded` | A committed receipt proves the claim only for the named scope, host, fixture, or corpus receipt. |
| `partial-live-with-fallback` | The editor can use the proof-backed path for scoped high-confidence cases and keeps fallback behavior for the rest. |
| `shadowed` | Receipts compare or explain behavior, but the compiler-backed path is not broad live behavior. |
| `deferred` | The support claim is not available yet; the next proof is named. |

## Operating Rules

- Promote a claim only when the row's proof command and status docs cover the
  claim being made.
- Do not use a stale parser corpus receipt for bucket-count or support-tier
  promotion.
- Do not use real-workspace latency alone as provider correctness proof.
- Do not use shadow receipts as live cutover claims.
- Keep dynamic Perl limitations visible instead of converting them into broad
  static-support claims.
