# Editor Intelligence Scorecard

This page is the stable landing point for editor-intelligence quality metrics.
Live numbers are generated by `cargo xtask ux-scorecard` and written to
[editor_ux.md](editor_ux.md).

## Quick summary

See [editor_ux.md](editor_ux.md) for the current measured scorecard, including:

- **Correctness** — hover, completion top-1/top-5, goto-definition exact-hit,
  document symbols, diagnostics, rename, and cross-file success rates.
- **Latency** — p50 and p95 baselines for completion, definition, diagnostics,
  document symbols, hover, and workspace symbols.

All metrics are regression-gated: `cargo xtask ux-scorecard --ratchet-check`
fails if any correctness rate or latency floor regresses below the stored
baseline in `.ci/metrics/baselines/editor_ux.json`.

## Regenerate

```bash
cargo xtask ux-scorecard
```

Output: `docs/project/status/editor_ux.md` (status page, default) and
`target/receipts/metrics/editor_ux_scorecard.json` (scorecard artifact,
default — override with `--output <path>`; see
`xtask/src/tasks/ux_scorecard.rs`'s `DEFAULT_OUTPUT`/`DEFAULT_STATUS_MD`).

## Gold corpus

Fixtures live under `test_corpus/gold/`. Each fixture directory contains:

- `fixture.pl` — Perl source used as the LSP document
- `expected_hover.json`, `expected_goto.json`, `expected_completion.json`,
  `expected_symbols.json`, `expected_rename.json` — per-kind assertion sidecars

Add new fixtures here to expand scenario coverage. Current coverage:
33 fixture directories spanning hover, goto-definition, completion,
document symbols, rename, diagnostics, `@INC`/`use lib` resolution, and
parse-error recovery (verify with `find test_corpus/gold -mindepth 1
-maxdepth 1 -type d | wc -l`).

(This is a separate metric from `editor_ux.md`'s own "N of 22 declared"
scenario count, which measures a different subsystem —
`crates/perl-lsp-ux-tests`'s `ux_scenario_*.rs` files against
`editor_ux_fixture_matrix.json`, tracked by #1426 — not the
`test_corpus/gold/` fixtures described in this section.)
