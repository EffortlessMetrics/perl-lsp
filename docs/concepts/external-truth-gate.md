# External-truth gate: CI verifies consistency, not truth

**Pattern.** Automated gates — CI, type-checks, the test suite, coverage, ripr — verify that an artifact is *internally consistent*: it compiles, its tests pass, its assertions agree with its own code. They do **not** verify that the artifact is *externally true*: that its claims match the world outside the repository — a library's real API, a language spec, a protocol, the actual behavior of a dependency. A change can be fully green and still be wrong.

**Why this matters more for AI-generated code.** A human author who is unsure of an external fact tends to leave a visible signal — a TODO, a value flagged for review, a question. An AI producer more often emits a *coherent fabrication*: it confidently states a wrong fact and, in the same pass, writes the test that confirms the wrong fact. The result is a closed loop of self-consistent wrongness in which every internal gate is green. CI cannot catch this by construction — the test encodes the lie.

**Worked example (perl-lsp-swarm #3118).** A feature adding hover/completion for Perl's `use builtin` functions shipped 16 function docs and 25 tests, all three required gates green. A correctness deep-review against `perldoc builtin` (the external oracle) found nine real bugs: a hallucinated `load_module` signature (three call-forms documented; the real API takes one argument), and version floors wrong in both directions — `inf`/`nan` documented as Perl 5.38 but actually 5.40 (a 5.38 user following the hover gets a runtime error), and four 5.36 functions mislabeled 5.38. The tests asserted `contains("5.38")` and passed — they encoded the hallucination. Only the external oracle exposed it.

**The gate.** For any change whose correctness depends on an external fact — a library API, a language/protocol spec, a documented behavior — a **correctness review against the external source is mandatory, and it runs *before* CI-gate-closure**, not as optional polish after. The internal gates (does it compile, do the tests pass, is coverage met) are necessary but insufficient; they answer "is this self-consistent," never "is this true."

**How to run it well.**
- **Name the oracle.** The reviewer consults the actual external source (the docs, the spec, the real registry, the running behavior) — not the diff. "Verified against perldoc.perl.org/builtin" is the load-bearing line; reasoning from the change alone re-derives the same lie.
- **Target the domain's specific failure mode**, not generic correctness: for an AST/IR lowering, *is there an alternative syntactic path to the same entity that is silently dropped?* (the NodeKind-blindness class); for a lexer disambiguator, *the genuinely-ambiguous hard cases*, not the easy ones; for an API-doc feature, *each documented fact, checked against the source*.
- **Audit test honesty.** A test that would still pass if the behavior were wrong verifies nothing — it documents intent. (`assert!(table.is_empty())` where the table could never contain the queried name; `assert!(result.is_some())` with no content check.) Demand assertions that *fail* when the behavior breaks, ideally with a positive control proving the negative is meaningful — e.g. assert a named sub IS collected, so the assertion that an anonymous one is NOT is discriminating rather than vacuous.
- **Verify the reviewer too.** Even a rigorous reviewer makes specific claims that need checking. On a sibling PR the reviewer cited an `is_empty()` method as existing at a specific line; it did not, and applying its suggested fix verbatim would not have compiled. Read the actual file before acting on any cited API or line number.

**Relation to the internal gates.** This does not replace CI — it is the gate CI structurally cannot be. Keep the consistency gates: they catch regressions, leaks, and real coverage gaps. Add the truth gate on top for anything whose correctness lives outside the artifact. The recurring trap is to treat a green gate stack as proof of correctness; it is only proof of self-consistency.
